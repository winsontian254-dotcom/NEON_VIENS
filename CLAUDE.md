# Neon Veins — notes for Claude

## Project shape
- The whole game is the single file `index.html` (Babylon.js from the CDN; never inline Babylon or add npm/build tooling to the web game).
- `android/` wraps it in an Android app (WebView). The APK is committed at `android/NeonVeins.apk`.

## Rule: every change to index.html also updates the Android app
Whenever you edit `index.html`, in the same commit:
1. Rebuild the APK: `python3 android/tools/build-apk.py` (needs `pip install pyaxml cryptography` and a JDK; no Android SDK required).
2. Commit `android/NeonVeins.apk` together with `index.html`.

If you changed native code (`android/app/src/**`, the manifest, or the build script), also bump `versionCode` (and `versionName`) in `android/version.json` before rebuilding: installed apps offer a one-tap update only when versionCode goes up.
Game-only changes do not need a version bump: installed apps download the new `index.html` from GitHub by themselves, and the rebuilt APK keeps the offline bundle current.

## Rule: announce player-visible changes (new-version prompt)
- Players get a "New version available" prompt (with change log) when `version.json` on GitHub Pages has a higher `build` than the `NV_BUILD` inside their loaded `index.html`.
- When you change the game in a way players should be told about, run `python3 tools/release.py "short change line" "another line"` (bumps `NV_BUILD` in index.html and adds an entry to `version.json`), then commit both with the rebuilt APK. Purely internal fixes don't need it.

## Android app facts
- The updater in `Updater.java` reads the branch `claude/festive-faraday-4v0m9s` of `winsontian254-dotcom/NEON_VIENS` (public GitHub API, no token). If the working branch changes, update `Updater.BRANCH` and bump versionCode.
- The APK is signed with the debug key in `android/keystore/`; keep using it so updates install over older versions.
- `window.NVAndroid` (JS bridge) exists only inside the app: `getMode()/setMode()` for Normal vs Cardboard, `share(name, text)` (share sheet, used by the Dossier), and the Back button calls `window.NVAndroidBack()`.

## Chinese translation (简体 / 繁體)
- Language is a setting (`lang`: 0 English, 1 Simplified, 2 Traditional; auto-detected from the browser on first run). `NV.I18n` translates dialogue in `UI.say` and the rest of the interface in the DOM (MutationObserver), by exact English text.
- Sources: `i18n/zh/bNN.tsv` (story lines by index into `NV.I18n.storyKeys()`), `i18n/zh/uiN.tsv` (English UI text → Simplified). Traditional is generated with OpenCC.
- After editing any translation, or the story data (NV_DATA), run `python3 tools/build_zh.py` (needs `pip install opencc-python-reimplemented`); it rewrites the `NV_ZH` block in index.html. New UI strings: add them to a `uiN.tsv`.

## 3D models (embedded)
- Models live in `assets/src/` with licences in `assets/manifest.json` (CC0 only). `python3 tools/embed_assets.py --slim` (with `GLTF_TRANSFORM_DIR` pointing at a folder with `@gltf-transform/core` + `functions` installed) writes them as base64 into the `NV_ASSETS` block of index.html; then rebuild the APK.
- `NV.Assets.inst(scene, name)` returns a copy with its own animation groups; every use keeps a code-built fallback.
- First-person weapons are built in Blender by `tools/blender/build_weapons.py` (`pip install bpy`; run `python3 tools/blender/build_weapons.py [-- pistol knife hands ...]`): `w_pistol, w_knife, w_smg, w_rifle, w_shotgun, w_sniper` plus two gloved fists `w_hand_grip` (closed round a vertical grip) and `w_hand_hold` (round a horizontal handle: knife, handguards; mirrored with a negative x scale for the left hand). Models are written in game axes (z = barrel direction) and each mesh is named by ROLE (`body metal grip dark acc heat glass glove sleeve`); `weaponModel` in index.html gives each role a material tinted with the weapon's faction colours, so one model serves every weapon of that archetype. `WGLB` / `WMUZ` / `WPOSE` / `HANDS` there list the models, muzzle positions, the knife's carry pose and where the fists sit; archetypes without a Blender model (rotary, launcher, hammer, baton, grenade, wrist, remote, designator, laser) still use the code-built ones. The receiver top is y = .082 so the code-built optics (`OPTICS`) bolt on; the sniper's scope is modelled (lenses at z .302 and `OPTICS.sniper.z`). `NV.Assets.pre(scene, names)` loads them when a level starts and `NV.Assets.sync` copies them instantly; until they arrive the code-built models stand in. Preview them without the game: the HTML viewer used while modelling is not committed; rendering a GLB in Babylon with `body/metal/...` materials by mesh name is enough.

## Character data
- A character is one of three lifepaths (`street`, `corp`, `nomad`) plus five attributes (`body ref int tech cool`, 3-8, lifepath minimums, four free points): `NV.BG` (`LIST`, `ATTR`, `floor`, `attrNorm`, `migrate`, `mods`) in index.html. Gameplay reads the numbers from `L.bg = NV.BG.mods(profile.tags, profile.attr)` (set in `NV.Level.start`; `mods([])` is neutral, used by multiplayer); never check tag ids directly. The numbers are explained only in the Dossier, so after changing any of them update `i18n/dossier/*` too.
- Appearance is `profile.look` (`jacket, visor, skin, hair, hairCol, eyes, ware`), normalised by `NV.LOOK.norm`. Profiles carry `v: 3` (`tags: [lifepath]`, `attr`); `NV.State.newGame` / `setProfile` fold any older profile through `NV.BG.migrate`. `ensureProfile` in the main loop converts v2 saves silently (with a toast) and asks about older ones through `UI.convertProfile`.
- The creator is `UI.create` (four screens; headings and microtext are `.notr` and translated with `tr()` by hand; art from `NV.Art`), `NV.Art.mount(canvas, 'street'|'corp'|'nomad'|'overlook')` paints the animated card scenes from code.

## The Dossier (long handbook + database tools)
- Source: `i18n/dossier/NN-name.en.txt` and its Simplified twin `.zh.txt` (`# ` section, `## ` sub-heading, blank line = paragraph; the two must have the same shape). `python3 tools/build_dossier.py` writes the English into the `NV_DOSSIER` script block of index.html and the English -> Chinese pairs into `i18n/zh/ui9.tsv`; then run `tools/build_zh.py`.
- `UI.dossier` is the reader: contents, query line (matches English and the current language), EXTRACT PASSAGE notes (`localStorage.nv_extract_v1`, `[section, item, hash]`), copy / download, and EXPORT MY RECORD (builds a text report from `nv_save_v1`). Inside the Android app downloads go through `window.NVAndroid.share(name, text)` (share sheet; older app builds fall back to the clipboard).

## Accounts server
- `server/` is the account API (Cloudflare Worker + D1 `neon-veins-accounts`, id in `server/wrangler.toml`; schema in `server/schema.sql`). It is deployed at https://neon-veins-api.winsontian254.workers.dev (`cd server && wrangler deploy` from a PC; this cloud session cannot reach Cloudflare).
- The game reads the API base from `DEFAULT_API` in `NV.Account` (index.html); `NV.Account.DEMO` is the number of chapters playable without an account.
- Admin export: `GET /api/admin/export?table=summary|users|friends|sessions|invites|saves` (`limit`, `offset`, `full=1` for save data, `redact=1` for users) exists only when the Worker secret `ADMIN_TOKEN` (24+ characters) is set; `python3 server/export.py` pages through it and writes private JSON/CSV files. It must never return `pass_hash`, `salt`, `iters`, session `token_hash`, invite codes or the `attempts` table. The owner sets the secret from a PC (`wrangler secret put ADMIN_TOKEN`); never ask the user to paste it into the chat. Test changes against a local fake D1 (Node's `node:sqlite`) since this session cannot reach Cloudflare.

## The city (hand-drawn)
- `NV.CITY_MAP` (above `NV.CityPlan` in index.html) is the authored map: a 32 x 32 grid of district letters, a block pattern per district (`a-o` templates, `.` plaza, `@` landmark site, `S` safe plaza), hand-placed `over` blocks, and the template library `T` (rects with height and facade `grid` / `ribbon` / `shed`).
- Landmark names from `NV.LANDMARKS` fill the `@` sites of their own district in reading order; if a district has too few, ordinary blocks make up the rest. Changing the map changes where everything is, so check that every district still has enough `@` sites and that the start plaza stays reachable.

## Authored interiors (missions, arenas, story spaces)
- `NV.LAYOUTS` (above the Helix Tower code in index.html) holds the hand-drawn plans, one character per 4 m cell: `#` wall, `.` floor, `S` start, `X` exit (scenes: where the cast gathers), `1-9` room centres, `T` terminal, `P` pickup, `e` enemy post, `m` medkit, `v` civilian, `c` crate, furniture `R B D C M K L Y N U` plus `F` vending machine, `H` hospital bed, `O` booth, `I` DJ deck, `J` pallets, `Z` cubicle, `E` tree or fountain, `W` workbench, `p` pew, `g` boiler, `o` cooker, `V` TV unit (cover, with their own collision size; a piece's front faces away from the wall behind it, `fs` in `buildDeco`), `r` rails (walkable). `kind` is `mission`, `arena` (17 x 17, keep the anchor cells free: the centre, the four spawn alcoves and the terminal/node/medkit spots `populate` uses) or `scene`; `pal` overrides the scene colours.
- `NV.layoutFor(op, ctx, wantCity)` and `NV.sceneInterior(heading)` choose the plan from the scene heading and objective text (never at random); `NV.Level.start` then sets `L.layout` and `L.city = false`. `parseLayout` / `buildDeco` in `NV.Level` read a plan and build its furniture. Outdoor operations still run in the city and get the arena plans as hand-placed cover.
- Test one in the browser with `#dev&allowgl&op=infiltrate&scene=THE%20HIVE&layout=factory` (`op=arena`, `op=scene` work too). Every plan must keep S and X connected to all its markers.

## Mission Director (twists)
- `NV.Level` has a director block above `/* ---- player actions ---- */`: `TWISTS` (name, label, line), `twistFor` (picks from the story text, then the chapter number and a hash; 12% stay plain; off for `op.tut`, co-op, free roam and scenes), `SETUP[id]`, `twistTick`, and the hooks `twInteract` (E on charges / hostage, started as a timed action in `L.tact`), `twOnExit` (lockdown / hostage hold the extraction), `twOnDown`, `twOnPickup`, `twOnObjective` (last terminal of a hack), `twRows`, `twPrompt`, `twTimer`, `twMarks`, `twDots`. `populate()` ends with `directorSetup`. State lives in `L.tw`; enemies it spawns carry `e.tw`.
- New twist = a `TWISTS` entry, a `SETUP` function (return false if the map has no room for it), whatever it needs in `twistTick` / the hooks, and its strings in `i18n/zh/ui10.tsv` (HUD rows, prompts and toasts are translated by exact text, so keep numbers in their own `<b>`). `reinforce(n)` / `farSpot(lo, hi)` bring alerted enemies from out of sight.
- `L.act` is the ACT NUMBER (1-5) and must never be reassigned; the timed action of a twist (planting, freeing) is `L.tact`.
- Complications: `COMPS` + `compsFor` (count by act/difficulty from a hash roll; `alarm` is dropped when the twist has a timer), `COMP_SETUP[id]`, `compTick`, `compOnAlert` (hook in `alertEnemy`), `compChips` (the `.cmps` chips in the HUD top) and `L.comp = { list, has }`. `L.dark` (blackout) scales enemy sight in `canSee`. Reinforcements (`reinforce`) are capped at eight alive.
- Enemy kinds beyond guard/heavy/drone/ice: `sniper` (laser telegraph then a fast shot: `sniperStep`, `laserOn`), `shield` (frontal damage cut in `weaponHit`; only taken down from behind or stunned), `rusher` (`rusherStrike`), `turret` (`makeTurret`, `e.hold`). `e.special` skips cover, flanking and grenades; `e.hold` keeps a post. Enemy bullets use a swept hit test, so fast shots cannot skip over you.
- Test them: `&comp=snipers,turrets` / `&comp=none`, `&kind=shield`, and `NV.Level.devApi()` (`addEnemy`, `weaponHit`, `emp`, `alertEnemy`, `hackDone`, `reinforce`).
- Test one: `#dev&allowgl&op=infiltrate&twist=sabotage` (`op=hack&twist=upload`, `op=explore&twist=ambush`, add `&layout=factory` for an authored plan). `NV.Level.devApi()` has `hackDone` and `disable` for scripting; headless runs go at a fraction of real time, so set timers (`L.tw.fuse`, `L.tact.t`) instead of waiting.

## The Nuallink (Ghost's implant link)
- `NV.Link` (above `NV.Account` in index.html) is the inbox: `M` is the authored message table (id, from, kind `msg|call|hack`, chapter id, `s` start / `d` done of that chapter, subject, paragraphs, encrypted flag), `WHO` the senders, `ASK` (ASCENSION answers by AI-sympathy tier), `FAQ` (Clawd) and `INTERCEPTS` (CrustAI practice texts). Save side: `S.link = { msgs: [{id, r read, p played}], ghost, mode: 'path'|'scram', locks, blocked, missed, uses, dec, tip }`; always read it through `NV.Link.st()` (chapter snapshots and old saves have no `link`).
- Delivery is by story position: `NV.Link.sync(NV.Link.at(ci, done))` runs at chapter start and chapter end in `Story` (`playChapter`, `run`); more than two new messages at once (an old save catching up) are filed silently, a single new call rings in the next level. ASCENSION speaks after chapter 4 (`NV.Link.unlocked()`).
- In a level (`NV.Level`, block "Nuallink" above `/* ---- player actions ---- */`): `L.lk = { avail, trace, tr, ch, cd, lockT, win, hackCd, stat, spoof, call, q }`. The link is off in tutorials, co-op and story scenes (`avail`); the TRACE only runs in solo infiltrate / hack / explore / retrieve. `lkTick` (from `updateMode`) climbs the trace while enemies are alerted (10 / s x `L.bg.det` x difficulty), 2 / s while suspicious, falls 0.7 / s unseen (not at all for 4 s after the last alert, `k.hot`); at 100 `lkLock` (Helix lock: trace 75, -20 energy, 45 s without ASCENSION, hostiles told your position, `reinforce(4-5)`); at 30+ while hunted `lkIntrusion` opens a 1.6 s window (V = `lkBlock`, 30 energy; a miss = minimap static 10 s via `L.lk.stat`, +15 trace). V (R3, touch LINK button) = `lkAssist` (Pathfinder: `L.arms.reveal` 12 s, Scramble: stun 14 m / 3 s; +45 trace, +AI sympathy; one per mission, two at AI sympathy 60+). N opens the screen from a level through `L.wantLink` + `L.wantPause`. The Signal Scrubber (`case 'scrub'`) calls `lkScrub`.
- Calls and Clawd's mission briefing use the card under the minimap (`lkCall(who, tag, lines)`; the briefing reuses the `TWISTS` / `COMPS` lines, which are already translated). Ghost Mode (`S.link.ghost`) switches all of it off.
- The screen is `UI.nuallink(tab)` (tabs INBOX, HELIX, ASCENSION, CLAWD; opened from the pause menu, the Journal and N). Encrypted messages and CrustAI texts decode with `Lk.scramble`. Every paragraph is translated by exact text in `i18n/zh/ui12.tsv`; `node` can check the data against the tsv (evaluate the `NV.Link` block with a stub `NV`). The numbers are explained in the Dossier section `i18n/dossier/12-nuallink.*.txt`: change them there when you tune the constants (`LK` in the level block).
- Test: `#dev&allowgl&op=infiltrate&twist=sabotage`, then in the console `NV.State.get().done=['1','2','3','4']`, `NV.Level.devApi()` has `lkAssist, lkKey, lkIntrusion, lkLock, lkCall, lkStart, lkScrub`; `NV.Level.debug().lk` is the state (set `lk.tr`, `lk.stat`, `lk.cd` instead of waiting).

## Interiors of every building
- `NV.Interiors` (above the Helix Tower code in index.html) generates a scene-kind plan per building: `make({ id, w, h, d, name?, lm?, type? })` registers `NV.LAYOUTS['in_b<id>' | 'in_l<id>']` (landmarks use `lm` + their name) and returns `{ layout, key, type, title, ix }`. `TYPES` (name, light colours, three lines of chatter), `MIX` (what each district's buildings are, by weight; `MIN_AREA` keeps big types out of small footprints), `build` (size 7-17 x 7-14 cells from the footprint, up to four rooms joined by two-cell doorways, furniture by a per-type recipe placed only where a flood fill from `S` keeps every floor cell reachable, `v` people, `P` stashes). Plans are deterministic from the building id, so a building is always the same place.
- What makes interiors differ: three layouts per type (`style`), `counter()` puts a counter one cell off the top wall with a person in the lane behind it, each room has a floor treatment (`leaves[i].kind`, drawn by `IXFLOOR` onto the level's `floor` mesh in `decorInterior`), a sign with a generated name (`SIGN`, on the wall facing the door), windows onto a night city, ceiling fittings per type (lanterns, pipes, fans, a mirror ball and beams, server lights, candle ring) with moving parts in `L.ixAnim` (run from `updateNpcs`), and a hue shift of the type's colours (`tone`). The plan keeps `leaves`, `sign`, `style` in `NV.LAYOUTS[key]`.
- Doors: `buildDoors` (in `NV.Level`, called from `populateFree` for solo free roam except the travel leg) puts a glowing frame (thin instances, one frame mesh per type in the type's colour, `L.doors`) on a street-facing side of every `CityPlan().buildings` entry and every landmark with a solid footprint (hall, factory, clinic, vault, dome, cathedral). E at a door (`freeInteract` `f:door`) ends the level with `{ enter: { b, x, z, yaw, hp } }`; `Story.freeRoam` then calls `enterBuilding`, which starts a `m: 'scene'` level with `op.interior = { type, ix, key }` (`populateInterior`: people with a TALK prop, stashes with a SEARCH prop paid once per save in `S.looted`, the door out is the `leave` prop) and afterwards puts you back with `NV.State.putSpot` (the free-roam spot key is rebuilt in `freeRoam`). Props can carry an `act` function (see `interact`). Interior levels have no spot key (`op.interior`), so quitting inside saves the street spot instead.
- Test: `#dev&allowgl&op=scene&interior=noodle&bid=12` (`bw`, `bh`, `bd` set the footprint and district, `interior` the type) or `#dev&allowgl&q=low&chapter=2` and walk to a door (`NV.Level.debug().doors`). ## Gear: cameras, breakers, locks, cyberware, workbench
- `NV.Ware` (above Accounts in index.html): `S.ware = { own, eq }` (3 slots), `LIST` (reflex armor tendon optic nano steps; name, description, cost), `RECIPES` (workbench), `S.picks` lockpicks via `picks()` / `addPicks()` (3 to begin with), `buy / toggle / can / craft`.
