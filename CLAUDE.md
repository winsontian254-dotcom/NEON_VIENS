# Neon Veins — notes for Claude

## Project shape
- The whole game is the single file `index.html` (Babylon.js from the CDN; never inline Babylon or add npm/build tooling to the web game).
- `android/` wraps it in an Android app (WebView). The APK is committed at `android/NeonVeins.apk`.

## Rule: every change to index.html also updates the Android app
Whenever you edit `index.html`, in the same commit:
1. Rebuild the APK: `python3 android/tools/build-apk.py` (needs `pip install pyaxml cryptography` and a JDK; no Android SDK required).
2. Commit `android/NeonVeins.apk` together with `index.html`.

If you changed native code (`android/app/src/**`, the manifest, or the build script), also bump `versionCode` (and `versionName`) in `android/version.json` before rebuilding: installed apps offer a one-tap update only when versionCode goes up.
Game-only changes do not need a version bump: installed apps download the new `index.html` from GitHub by themselves, and the rebuilt APK keeps the offline bundle current.

## Rule: announce player-visible changes (new-version prompt)
- Players get a "New version available" prompt (with change log) when `version.json` on GitHub Pages has a higher `build` than the `NV_BUILD` inside their loaded `index.html`.
- When you change the game in a way players should be told about, run `python3 tools/release.py "short change line" "another line"` (bumps `NV_BUILD` in index.html and adds an entry to `version.json`), then commit both with the rebuilt APK. Purely internal fixes don't need it.

## Android app facts
- The updater in `Updater.java` reads the branch `claude/festive-faraday-4v0m9s` of `winsontian254-dotcom/NEON_VIENS` (public GitHub API, no token). If the working branch changes, update `Updater.BRANCH` and bump versionCode.
- The APK is signed with the debug key in `android/keystore/`; keep using it so updates install over older versions.
- `window.NVAndroid` (JS bridge) exists only inside the app: `getMode()/setMode()` for Normal vs Cardboard, `share(name, text)` (share sheet, used by the Dossier), and the Back button calls `window.NVAndroidBack()`.

## Chinese translation (简体 / 繁體)
- Language is a setting (`lang`: 0 English, 1 Simplified, 2 Traditional; auto-detected from the browser on first run). `NV.I18n` translates dialogue in `UI.say` and the rest of the interface in the DOM (MutationObserver), by exact English text.
- Sources: `i18n/zh/bNN.tsv` (story lines by index into `NV.I18n.storyKeys()`), `i18n/zh/uiN.tsv` (English UI text → Simplified). Traditional is generated with OpenCC.
- After editing any translation, or the story data (NV_DATA), run `python3 tools/build_zh.py` (needs `pip install opencc-python-reimplemented`); it rewrites the `NV_ZH` block in index.html. New UI strings: add them to a `uiN.tsv`.

## 3D models (embedded)
- Models live in `assets/src/` with licences in `assets/manifest.json` (CC0 only). `python3 tools/embed_assets.py --slim` (with `GLTF_TRANSFORM_DIR` pointing at a folder with `@gltf-transform/core` + `functions` installed) writes them as base64 into the `NV_ASSETS` block of index.html; then rebuild the APK.
- `NV.Assets.inst(scene, name)` returns a copy with its own animation groups; every use keeps a code-built fallback.
- First-person weapons are built in Blender by `tools/blender/build_weapons.py` (`pip install bpy`; run `python3 tools/blender/build_weapons.py [-- pistol knife hands ...]`): `w_pistol, w_knife, w_smg, w_rifle, w_shotgun, w_sniper` plus two gloved fists `w_hand_grip` (closed round a vertical grip) and `w_hand_hold` (round a horizontal handle: knife, handguards; mirrored with a negative x scale for the left hand). The glove is built from overlapping tubes and balls, then fused (`Model.fuse['glove'] = (voxel size, kept ratio)`: voxel remesh, Smooth modifier, Decimate, full smooth shading), because 8-sided tubes shaded with a 40 degree angle limit rendered as flat facets ("ugly fingers"); fingers are spaced a little apart so a groove survives the fusing, the thumb has a thick root (the web of the hand). Run `python3 tools/blender/build_weapons.py -- hands` with the bpy venv, then `embed_assets.py --slim`. Models are written in game axes (z = barrel direction) and each mesh is named by ROLE (`body metal grip dark acc heat glass glove sleeve`), and parts that move are separate nodes named `<role>.<part>` (`metal.mag`, `body.slide`, `metal.bolt`, `grip.pump`: `Model.part_on('mag') ... part_off()` in the script; parts are `mag` (pistol, smg, rifle, sniper), `slide` (pistol), `bolt` (smg, rifle, sniper), `pump` (shotgun)) which `weaponModel` wraps in `TransformNode`s returned as `parts`; `weaponModel` in index.html gives each role a material tinted with the weapon's faction colours, so one model serves every weapon of that archetype. `WGLB` / `WMUZ` / `WPOSE` / `HANDS` there list the models, muzzle positions, the knife's carry pose and where the fists sit; archetypes without a Blender model (rotary, launcher, hammer, baton, grenade, wrist, remote, designator, laser) still use the code-built ones. The receiver top is y = .082 so the code-built optics (`OPTICS`) bolt on; the sniper's scope is modelled (lenses at z .302 and `OPTICS.sniper.z`). `NV.Assets.pre(scene, names)` loads them when a level starts and `NV.Assets.sync` copies them instantly; until they arrive the code-built models stand in. Preview them without the game: the HTML viewer used while modelling is not committed; rendering a GLB in Babylon with `body/metal/...` materials by mesh name is enough.

## Realistic humans (the human kit, MakeHuman head / hands / eyes, skin, hair)
- Every person (enemies, civilians, pedestrians, story NPCs, Ghost, other players, the creator preview) is built from one Blender-made kit, `assets/src/human_kit.glb` (embedded as `human_kit`, manifest flag `keep_attributes` so `--slim` keeps the UVs). Source: `tools/blender/build_humans.py` (`pip install bpy numpy`; `python3 tools/blender/build_humans.py -- body` writes the kit, ~1 min; then `embed_assets.py --slim` and rebuild the APK). Parts: `torso pelvis leg_u leg_l foot arm_u arm_l hand head eyes` (**no neck and no ear parts**: the head carries its own), hair `hair_buzz hair_undercut hair_mohawk hair_bob hair_long hair_bun hair_braids`, `hood`, `cap`, plus `<name>_lo` decimated copies and `head_lo2` for distance. The torso is a loose zip jacket whose cloth detail (zip, welts, collar, rib hem, seams) is painted by `jacketCanvas` in `NV.Human` onto the torso's UVs (`JY` / `JR` in `jacketCanvas` list the profile rows and must follow `torso()`; the collar rows are centred back of the torso axis, c2 = -.04, so the neck cut sits inside the collar). The `MOUNT` table (Blender side) must match the rig offsets in `rigBuild` (arms at x +-.228, y 1.47; legs at x +-.105; hand -.34 under the elbow; head +.13 over the neck pivot); the sleeve (`arm_l`) ends .04 higher than it used to, so the wrist shows and the hand's thumb does not poke through it. Clothes: sleeves taper from the shoulder (no balloon), the top of the forearm sits inside the upper arm, the pelvis narrows to a small fork between the thighs, and `AO_SETTINGS` keeps the baked occlusion light (.7-.78 floor) on `arm_u arm_l pelvis leg_u leg_l`, where two overlapping parts used to leave dark bands at the elbow and knee. Trousers and boots are no longer near-black (`fromLook` / `forNpc` / `forCiv` pick a charcoal tinted by the jacket and brown-grey boots) because the seams and folds cannot show on black; soldiers' pelvis uses the suit cloth. The jacket's creases are a few long soft folds. The hand has vertex tints: warm skin, redder knuckles and paler nails (`hand()` uses the fingertip and knuckle positions `hand_geometry` returns).
- **Faces are blank by design (the owner gave up on faces twice: no 3D features, no face textures).** `FACE_DETAIL = False` in `build_humans.py`: `blank_face(geo, ...)` cuts the nose, lips, eyelids and the cavities behind them out of the face area of the MakeHuman head, relaxes what is left into a smooth dome (radius from the skull centre, 1200 Laplacian passes, rest of the head fixed) and closes the holes with flat fans; no eyes mesh is exported and the lip / brow / nose tints are skipped (ears keep theirs). In `NV.Human`, `eyes()` / `eyeProtos()` return nothing and `mats()` creates no eye / brow / lash material when the kit has no `eyes` template (`HAS_EYES`), and the face skin has no pore normal map. The eye / brow / lash code, `NV_IMGS.eye_brown` and `assets/src/makehuman/eyes` are kept: set `FACE_DETAIL = True`, rebuild the kit and the full face (with real eyes, brows, lashes and lip tints) comes back. Do not spend effort on faces unless the owner asks again.
- **Head, hands and eyes are MakeHuman's base mesh** (CC0, `assets/src/makehuman/`, attribution in its README; the assets repo with hair / skin textures was not reachable, so those stay procedural). `tools/blender/mh_import.py` (pure numpy, no Blender needed: `python3 mh_import.py` prints sizes) reads the .obj / .mhskel / .mhw / .mhclo / .target files: `head_geometry()` (head + neck cut flat at `NECK_CUT`, cylindrical UVs, `masks` for lips / ears / nose from the morph targets' displacement, gated by position and faded: lips = 1 cm above and below the mouth line), `hand_geometry(mh, curl)` (relaxed hanging right hand with curled fingers by forward kinematics on the .mhw weights, forearm stub cut at y .052), `eyes_geometry()` (the high-poly eyeball fitted by its .mhclo; **half of its faces are the glassy cornea shell, UV on the pale disc in the corner of the texture: they are dropped**, otherwise the iris is hidden). `build_humans.py` wraps them: `mh_part`, `mh_head_parts` (lip / brow / ear / nose tints as vertex colours; `head`, `head_lo`, `head_lo2`, `eyes`), `build_head_surface` + `head_pos_surface` (a Taubin-smoothed copy of the head with the ears flattened into a membrane, sampled on a blurred 360 x 181 radius grid `SURF_R` from the skull centre; hair, hoods and caps are fitted to it by `hair_sheet`, which finds the polar angle for a given end height by bisection and lays strands along a mostly radial normal (`hnorm`: the true surface normal alone jumps about over the ear and the jaw and gave shards)). Two hair sheets must never overlap in longitude (the bob's / long hair's fringe stops where the side sheets start) or they cut through each other in a row of teeth. The old ellipsoid head, `FEATURES`, `hand_procedural`, `ear_part` and `BLANK_FACE` code stays in `build_humans.py` for reference only. Baked ambient occlusion is the vertex colour; hair and the `_lo` copies are left out of the occluder BVH.
- `NV.Human` (index.html, after `NV.Assets`): `load(scene)` (parses the kit once per page into game-axes vertex data, `kitData`; hidden template meshes `h_<name>` and mirrored `_L` versions of the asymmetric parts; no negative scaling anywhere), `ready(scene)`, `mats(scene, spec)` (face / plain skin, eye, brow, lash, jacket, pants, boots, glove, hair, hood, cap), `part(scene, key, side, M)` (a rig segment with LOD levels: lo copy, `lo2` for the head, then nothing; `DIST.head = [4, 90, 22]`), `proto(...)` (an instancing source parked at y -1000), `dress` (`eyes()` + hair style), `eyeProtos(scene, M)` (eyes, brows and lashes as instancing sources for pedestrians, gone beyond ~16 m), `gear(scene, head, { eyes, ware, glow, maskMat })` (visor, shades, glowing optics, implants as `strip(scene, ys, arcFrom, arcTo, offset, material, steps)` ribbons that follow the head by raycast; pass several `ys` rows where the surface is not flat, or a two-row ribbon cuts a chord through the brow ridge), `lashRibbon` (lashes lie on a skin of the eyeball because the head has an opening there), `assemble`, `preview(canvas, look, opt)` (the creator's 3D figure on its own small engine) and the specs `fromLook(look)`, `forNpc(name, info, col)`, `forCiv(...)`.
- Skin is a tiling tone texture with a pore normal map (`skinMat`, tiles 27 on the head / 100 elsewhere) plus the vertex-colour tints; **the eye is MakeHuman's CC0 iris photo** (`assets/src/makehuman/eye_brown.jpg`, embedded as `NV_IMGS.eye_brown` by `embed_assets.py` for manifest entries with `"image": true`) recoloured in `irisCanvas` (HSV shift to the wanted iris colour; glowing optics use an emissive copy); brows and lashes are alpha-**blended** hair strokes on ribbons (`browCanvas` 256 x 96, `lashCanvas` 128 x 40). **A ribbon's v = 0 is its lowest row, which is the top of the canvas, so both canvases flip with `g.scale(1, -1)` before drawing**; the brow is arched with a thick inner end tapering to the temple, on a ribbon 2 cm tall and 5 cm long. Hair is an alpha-cut strand texture (`hairCanvas`), clothes are matte (`cloth(scene, hex, kind)`: `jacket` atlas, `tile` twill + normal map, `leather`), canvases are cached (`CV`), textures belong to a scene, half-size on weak devices. Materials are cached per scene by colour. The face atlas / `face()` painter / `glowMask` / `BLANK_FACE` of Builds 41-43 are dead code now.
- Integration in `NV.Level`: `NV.Human.load` runs in `start` before `buildScene`'s result is populated (`proceed`); `buildKitProtos()` builds the shared instanced soldier parts (`L.kproto` is only set when the essential parts exist: `torso pelvis thigh shin foot* uarm* farm* hand* head0-2 plate helm`; it silently falls back to the code-built soldiers when one is missing) and `makeHuman` instances them; `addCivilian`, the pedestrians (`PK` types in `populateFree`, with `T.eyes = H.eyeProtos(...)`) and `npcKit` (called from `makeNpc` for people; Ghost and anyone with a `look` follow it) use `rigBuild(root, mk, armor, kit)` with kit part keys `thigh shin foot uarm farm hand` that ask for a side; **kit mode never asks for a neck**. Every path keeps the old code-built humans as the fallback when the kit is missing (`NV.Human.ready(scene)` false or quality `potato`).
- The creator (`UI.create`, `mount3d`) lays a live 3D canvas (`.cp3d`) over the 2D bust on the appearance and attributes screens; the bust stays as the fallback until the kit has loaded.
- Look development without a level: open the title (or the creator) and, in the console, `NV.Human.preview(canvas, look, { still: 1, yaw: .5, cam: [0, 1.83, .62], target: [0, 1.81, 0], fov: .4 })` renders a figure on any canvas (`cam [0, 1.08, 3.7]`, fov .55 shows the whole body, `fov: .16` at the eyes is a macro); `NV.Human.browCanvas(hex)` / `lashCanvas(hex)` return the canvases. Draw a coloured edge on a texture through `material.diffuseTexture.getContext()` to learn how it maps onto a ribbon.
- Test: `#dev&allowgl&op=scene&scene=NOAH%20CLINIC&layout=s_clinic`, then `NV.Level.devApi().makeNpc({ name: 'Ghost', kind: 'human', look: NV.LOOK.PRESETS[1] }, x, z)` in front of the player; `addEnemy('guard', x, z)`, `addCivilian(x, z)`. `NV.Level.debug().kproto` is null when the soldiers fell back. Count LOD with `mesh.getLOD(camera)` on `L.scene.getActiveMeshes()`.

## Character data
- A character is one of three lifepaths (`street`, `corp`, `nomad`) plus five attributes (`body ref int tech cool`, 3-8, lifepath minimums, four free points): `NV.BG` (`LIST`, `ATTR`, `floor`, `attrNorm`, `migrate`, `mods`) in index.html. Gameplay reads the numbers from `L.bg = NV.BG.mods(profile.tags, profile.attr)` (set in `NV.Level.start`; `mods([])` is neutral, used by multiplayer); never check tag ids directly. The numbers are explained only in the Dossier, so after changing any of them update `i18n/dossier/*` too.
- Appearance is `profile.look` (`jacket, visor, skin, hair, hairCol, eyes, ware`), normalised by `NV.LOOK.norm`. Profiles carry `v: 3` (`tags: [lifepath]`, `attr`); `NV.State.newGame` / `setProfile` fold any older profile through `NV.BG.migrate`. `ensureProfile` in the main loop converts v2 saves silently (with a toast) and asks about older ones through `UI.convertProfile`.
- The creator is `UI.create` (four screens; headings and microtext are `.notr` and translated with `tr()` by hand; art from `NV.Art`), `NV.Art.mount(canvas, 'street'|'corp'|'nomad'|'overlook')` paints the animated card scenes from code.

## The Dossier (long handbook + database tools)
- Source: `i18n/dossier/NN-name.en.txt` and its Simplified twin `.zh.txt` (`# ` section, `## ` sub-heading, blank line = paragraph; the two must have the same shape). `python3 tools/build_dossier.py` writes the English into the `NV_DOSSIER` script block of index.html and the English -> Chinese pairs into `i18n/zh/ui9.tsv`; then run `tools/build_zh.py`.
- `UI.dossier` is the reader: contents, query line (matches English and the current language), EXTRACT PASSAGE notes (`localStorage.nv_extract_v1`, `[section, item, hash]`), copy / download, and EXPORT MY RECORD (builds a text report from `nv_save_v1`). Inside the Android app downloads go through `window.NVAndroid.share(name, text)` (share sheet; older app builds fall back to the clipboard).

## The city (hand-drawn)
- `NV.CITY_MAP` (above `NV.CityPlan` in index.html) is the authored map: a 32 x 32 grid of district letters, a block pattern per district (`a-o` templates, `.` plaza, `@` landmark site, `S` safe plaza), hand-placed `over` blocks, and the template library `T` (rects with height and facade `grid` / `ribbon` / `shed`).
- Landmark names from `NV.LANDMARKS` fill the `@` sites of their own district in reading order; if a district has too few, ordinary blocks make up the rest. Changing the map changes where everything is, so check that every district still has enough `@` sites and that the start plaza stays reachable.

## Authored interiors (missions, arenas, story spaces)
- `NV.LAYOUTS` (above the Helix Tower code in index.html) holds the hand-drawn plans, one character per 4 m cell: `#` wall, `.` floor, `S` start, `X` exit (scenes: where the cast gathers), `1-9` room centres, `T` terminal, `P` pickup, `e` enemy post, `m` medkit, `v` civilian, `c` crate, furniture `R B D C M K L Y N U` plus `F` vending machine, `H` hospital bed, `O` booth, `I` DJ deck, `J` pallets, `Z` cubicle, `E` tree or fountain, `W` workbench, `p` pew, `g` boiler, `o` cooker, `V` TV unit (cover, with their own collision size; a piece's front faces away from the wall behind it, `fs` in `buildDeco`), `r` rails (walkable). `kind` is `mission`, `arena` (17 x 17, keep the anchor cells free: the centre, the four spawn alcoves and the terminal/node/medkit spots `populate` uses) or `scene`; `pal` overrides the scene colours.
- `NV.layoutFor(op, ctx, wantCity)` and `NV.sceneInterior(heading)` choose the plan from the scene heading and objective text (never at random); `NV.Level.start` then sets `L.layout` and `L.city = false`. `parseLayout` / `buildDeco` in `NV.Level` read a plan and build its furniture. Outdoor operations still run in the city and get the arena plans as hand-placed cover.
- Test one in the browser with `#dev&allowgl&op=infiltrate&scene=THE%20HIVE&layout=factory` (`op=arena`, `op=scene` work too). Every plan must keep S and X connected to all its markers.

## Mission Director (twists)
- `NV.Level` has a director block above `/* ---- player actions ---- */`: `TWISTS` (name, label, line), `twistFor` (picks from the story text, then the chapter number and a hash; 12% stay plain; off for `op.tut`, co-op, free roam and scenes), `SETUP[id]`, `twistTick`, and the hooks `twInteract` (E on charges / hostage, started as a timed action in `L.tact`), `twOnExit` (lockdown / hostage hold the extraction), `twOnDown`, `twOnPickup`, `twOnObjective` (last terminal of a hack), `twRows`, `twPrompt`, `twTimer`, `twMarks`, `twDots`. `populate()` ends with `directorSetup`. State lives in `L.tw`; enemies it spawns carry `e.tw`.
- New twist = a `TWISTS` entry, a `SETUP` function (return false if the map has no room for it), whatever it needs in `twistTick` / the hooks, and its strings in `i18n/zh/ui10.tsv` (HUD rows, prompts and toasts are translated by exact text, so keep numbers in their own `<b>`). `reinforce(n)` / `farSpot(lo, hi)` bring alerted enemies from out of sight.
- `L.act` is the ACT NUMBER (1-5) and must never be reassigned; the timed action of a twist (planting, freeing) is `L.tact`.
- Complications: `COMPS` + `compsFor` (count by act/difficulty from a hash roll; `alarm` is dropped when the twist has a timer), `COMP_SETUP[id]`, `compTick`, `compOnAlert` (hook in `alertEnemy`), `compChips` (the `.cmps` chips in the HUD top) and `L.comp = { list, has }`. `L.dark` (blackout) scales enemy sight in `canSee`. Reinforcements (`reinforce`) are capped at eight alive.
- Enemy kinds beyond guard/heavy/drone/ice: `sniper` (laser telegraph then a fast shot: `sniperStep`, `laserOn`), `shield` (frontal damage cut in `weaponHit`; only taken down from behind or stunned), `rusher` (`rusherStrike`), `turret` (`makeTurret`, `e.hold`). `e.special` skips cover, flanking and grenades; `e.hold` keeps a post. Enemy bullets use a swept hit test, so fast shots cannot skip over you.
- Test them: `&comp=snipers,turrets` / `&comp=none`, `&kind=shield`, and `NV.Level.devApi()` (`addEnemy`, `weaponHit`, `emp`, `alertEnemy`, `hackDone`, `reinforce`).
- Test one: `#dev&allowgl&op=infiltrate&twist=sabotage` (`op=hack&twist=upload`, `op=explore&twist=ambush`, add `&layout=factory` for an authored plan). `NV.Level.devApi()` has `hackDone` and `disable` for scripting; headless runs go at a fraction of real time, so set timers (`L.tw.fuse`, `L.tact.t`) instead of waiting.

## The Nuallink (Ghost's implant link)
- `NV.Link` (above `NV.Account` in index.html) is the inbox: `M` is the authored message table (id, from, kind `msg|call|hack`, chapter id, `s` start / `d` done of that chapter, subject, paragraphs, encrypted flag), `WHO` the senders, `ASK` (ASCENSION answers by AI-sympathy tier), `FAQ` (Clawd) and `INTERCEPTS` (CrustAI practice texts). Save side: `S.link = { msgs: [{id, r read, p played}], ghost, mode: 'path'|'scram', locks, blocked, missed, uses, dec, tip }`; always read it through `NV.Link.st()` (chapter snapshots and old saves have no `link`).
- Delivery is by story position: `NV.Link.sync(NV.Link.at(ci, done))` runs at chapter start and chapter end in `Story` (`playChapter`, `run`); more than two new messages at once (an old save catching up) are filed silently, a single new call rings in the next level. ASCENSION speaks after chapter 4 (`NV.Link.unlocked()`).
- In a level (`NV.Level`, block "Nuallink" above `/* ---- player actions ---- */`): `L.lk = { avail, trace, tr, ch, cd, lockT, win, hackCd, stat, spoof, call, q }`. The link is off in tutorials, co-op and story scenes (`avail`); the TRACE only runs in solo infiltrate / hack / explore / retrieve. `lkTick` (from `updateMode`) climbs the trace while enemies are alerted (10 / s x `L.bg.det` x difficulty), 2 / s while suspicious, falls 0.7 / s unseen (not at all for 4 s after the last alert, `k.hot`); at 100 `lkLock` (Helix lock: trace 75, -20 energy, 45 s without ASCENSION, hostiles told your position, `reinforce(4-5)`); at 30+ while hunted `lkIntrusion` opens a 1.6 s window (V = `lkBlock`, 30 energy; a miss = minimap static 10 s via `L.lk.stat`, +15 trace). V (R3, touch LINK button) = `lkAssist` (Pathfinder: `L.arms.reveal` 12 s, Scramble: stun 14 m / 3 s; +45 trace, +AI sympathy; one per mission, two at AI sympathy 60+). N opens the screen from a level through `L.wantLink` + `L.wantPause`. The Signal Scrubber (`case 'scrub'`) calls `lkScrub`.
- Calls and Clawd's mission briefing use the card under the minimap (`lkCall(who, tag, lines)`; the briefing reuses the `TWISTS` / `COMPS` lines, which are already translated). Ghost Mode (`S.link.ghost`) switches all of it off.
- The screen is `UI.nuallink(tab)` (tabs INBOX, HELIX, ASCENSION, CLAWD; opened from the pause menu, the Journal and N). Encrypted messages and CrustAI texts decode with `Lk.scramble`. Every paragraph is translated by exact text in `i18n/zh/ui12.tsv`; `node` can check the data against the tsv (evaluate the `NV.Link` block with a stub `NV`). The numbers are explained in the Dossier section `i18n/dossier/12-nuallink.*.txt`: change them there when you tune the constants (`LK` in the level block).
- Test: `#dev&allowgl&op=infiltrate&twist=sabotage`, then in the console `NV.State.get().done=['1','2','3','4']`, `NV.Level.devApi()` has `lkAssist, lkKey, lkIntrusion, lkLock, lkCall, lkStart, lkScrub`; `NV.Level.debug().lk` is the state (set `lk.tr`, `lk.stat`, `lk.cd` instead of waiting).

## Interiors of every building
- `NV.Interiors` (above the Helix Tower code in index.html) generates a scene-kind plan per building: `make({ id, w, h, d, name?, lm?, type? })` registers `NV.LAYOUTS['in_b<id>' | 'in_l<id>']` (landmarks use `lm` + their name) and returns `{ layout, key, type, title, ix }`. `TYPES` (name, light colours, three lines of chatter), `MIX` (what each district's buildings are, by weight; `MIN_AREA` keeps big types out of small footprints), `build` (size 7-17 x 7-14 cells from the footprint, up to four rooms joined by two-cell doorways, furniture by a per-type recipe placed only where a flood fill from `S` keeps every floor cell reachable, `v` people, `P` stashes). Plans are deterministic from the building id, so a building is always the same place.

## Audio (everything is synthesised)
- `NV.Audio` (top of index.html, just before the character voice profiles): no samples, only WebAudio. Graph: voices -> buses `music / sfx / ui / amb` -> `master` -> compressor (the limiter) -> trim -> destination. Shared sends: `room` and `hall` convolvers (generated impulse responses), a `slap` delay; the music has its own `pump` gain (the kick dips the pads), reverb and a dotted-eighth delay. `volumes()` maps the three settings sliders to the buses (sfx and ui x3, amb x.22, music x.65, the music and ambience duck under dialogue); the factors were measured, so re-measure (below) after changing a bus.
- API: `init`, `setMood`, `duck`, `applyVolumes` (unchanged); `sfx(name, arg, at)`, `engine(rpm, boost, load)`, `tires(level)`; new `listen(x, y, z, yaw)` (every frame from `update`), `setSpace({ space: 'street' | 'room' | 'hall' | 'tunnel' | 'none', surface: 'wet' | 'concrete' | 'metal' | 'tile' | 'carpet' })`, `ambience(kind, { rain })`, `heart(k)` (0 = off), `alarm(on)`, `stinger('win' | 'fail' | 'chapter')`. Test hooks: `render(fn, secs)` (runs `fn` into an `OfflineAudioContext` with the same graph), `renderMusic(mood, secs)`, `sfxNames()`, `now()` (current ambience kind, space, surface, mood) and `A.err` (the last exceptions swallowed inside `sfx`).
- A world sound takes a position as the third argument: `{ x, z, y?, ref?, occ?, max? }` (`ref` = the distance at which it is full volume, `occ` = behind a wall). `dest()` turns it into distance gain, an air-absorption lowpass, rear darkening, a stereo pan from the listener's yaw, an arrival delay (d / 343 s, capped) and reverb sends that grow with distance. Anything without `at` is played flat (UI, the player's own gun, HUD).
- Sounds are in the `SFX` table (`ui select back type choice unlock exit glitch hack hackok hackfail aimIn aimOut dry beep lock lockok zap scan alert sus radio shoot eshoot rl hit hurt down kill headshot swing stab shield zip ricochet impact boom crash boss step jump land dash emp pickup door vent horn whistle clatter cam sparkle shift`), built from the primitives `osc`, `nz` (filtered noise with a sweep), `bell` (FM), `click`, `thud`. Guns are one `gun()` recipe driven by the `GUN` table (`pistol smg rifle shotgun sniper heavy`; `rail`, `laser` and `launcher` have their own branches, `rotary` uses `heavy`); `arg.m` is the family and `arg.s` the suppressed flag; `eshoot` takes the same `m`. `step` takes `{ v }` (volume factor), the surface comes from `setSpace`. `MINGAP` rate-limits spammy sounds, `CRIT` lists the ones that are never dropped when more than 64 voices are alive.
- Loudness: `TRIM[key]` multiplies a sound so that its measured peak sits at the target (pistol -12 dBFS ... shotgun and explosion -7, UI about -24, steps -31). Re-measure with a headless page: load the module (`sed -n '/^NV.Audio = /,/^})();/p' index.html`), `await A.render(() => A.sfx(n, a), 3)` for each sound, and compute the peak and rms; there must be no NaN, no clipping and `A.err` empty. Spectrograms were used to tune the tails. Nobody has listened to this on speakers in this session: treat the balance as untuned and expect the owner to ask for changes.
- Music: a tick-scheduled 16-step engine (25 ms timer, 0.14 s look-ahead). A mood is a `MOODS` entry (chord progression `Q`, pattern set `PAT`, layers: pad, bass, arp, drums, a seeded two-bar lead hook per mood, bells, drone, a riser every 8th bar and an impact on mood changes). Add a mood = a `MOODS` entry plus its callers.
- Ambience: `ambience(kind)` loops filtered-noise beds (plus a synthesised rain buffer) and schedules random events (sirens, horns, thunder, drips, clanks, typing, crowd). Kinds: `city rooftop apartment facility factory club noodle clinic office server hall vault room title`; interior types and layouts are mapped by `AMB_OF`. `LVL[kind]` is the loudness of each bed.
- Wiring in `NV.Level`: `audioSetup(op)` (before `lkSetup(op)` in `proceed`) picks space, surface and ambience from the interior type, layout key, apartment / void or the city (`L.rain` = wet); `update` sets the listener and the low-health heartbeat; `end()` returns to the title ambience and silences the alarm and heartbeat; `finish()` plays the stinger. Enemy fire (`eshoot`), hits, deaths, enemy footsteps, explosions (`boomFx`, boss, camera, uplink, cars) are positional; the whizz of a near-miss is in `updateBullets` (`b.zt`), `killMark()` plays the kill-confirm, `alarmTrip` starts the siren for 9 s. New gameplay sound = an `SFX` entry (and a `TRIM` key) and a call with a position.

## Cars and drifting
- Block "player driving" in `NV.Level` (`CAR_STYLES`, `carProtos`, `makeCar`, `carVis`, `carFx`, `cfxPuff` / `cfxTick`, `skidMark`, `CAR`, `carHurt`, `driftEnd`, `updateDrive`, `driveCamera`). A car has `x z yaw` (body heading), a velocity vector `vx vz` (`sp` = its length, `vh` = its heading, `speed` = the signed part along the nose, which `carVis`, the speedo and traffic still read) and `hp` (100). Traffic cars keep the old lane state (`along`, `axis`, `dir`) and only borrow `speed`, `brakeOn` and the visuals.
- `makeCar(x, z, yaw, kind, style?)`: `style` is `coupe | sedan | van` (random otherwise; side-view profiles in `CAR_STYLES`, extruded by `NV.extrude`). The four wheels sit on hub nodes `c.wheels` (FL, FR, RL, RR: the front pair turns with `c.steerV`, all spin from `c.speed`), `c.brk` is the brake-light bar (`c.brakeOn`) and `c.flames` the exhaust flames (`c.flame`).
- `updateDrive`: engine / brake along the nose, then grip. The tyres remove sideways speed at `grip` per second (9 on the road, down to ~2 when steering hard at speed, 4.2 braking into a corner above 12 m/s, 1.7 on the handbrake, ~1.9 while holding a slide under power). Yaw rate = steering x `rate` (falls with speed) + `slip` x `stab` (the self-aligning pull towards the travel direction, weaker on the handbrake and while holding a slide). `c.slip` is the angle between nose and velocity; |slip| > .3 at over 10 m/s is a drift (`c.dr` seconds). The whole model was tuned in a node harness: stub `L`, `NV`, `U` and the helpers and run the function body between `const CAR =` and `function driveCamera` at 60 fps (a headless browser runs at a tenth of real time, so slide behaviour cannot be judged there).
- Score: `D.df = { score, combo, t }` (speed x |slip| x 6 per second, combo +1 every 2 s up to x5); `driftEnd` banks `points / 20` credits when the slide has been over for .8 s and gives a mini-turbo (`c.tb` = points / 250 s, .8-2.5 s) for 150+ points; a hit over 8 m/s loses it. Collisions test each axis on its own (`blockX / blockZ`); `carHurt(c, hit)` costs `(hit - 5) x 4.2` hp above 6 m/s and calls `carExplode` at 0; two cars above 22 m/s both explode, slower they bump and take damage.
- Effects: pooled tyre / damaged-engine smoke (`L.cpuff`), skid marks (`L.skids`, instances of one flat plane, fade after 12-16 s), sparks on scrapes, body roll / pitch, camera roll with the slip and a wider FOV with boost or turbo. Camera heading `c.ch` follows the velocity heading blended with the nose. Audio: `NV.Audio.engine(rpm, boost, load)` (gears `GT` thresholds 7 / 14 / 21 / 28 m/s) and `NV.Audio.tires(level)`.
- HUD: `.speedo` (speed, rev bar, gear, car health bar) and the `.drift` chip, both direct children of `#hud`; class names must not collide with global ones (`.ds` and `.dk` already exist). The weapon panel hides while driving. Multiplayer sends the body heading (`cy = c.yaw`). Strings: `i18n/zh/ui27.tsv` and two patterns in `tools/build_zh.py`; numbers: Dossier `21-driving`.
- Test: `#dev&allowgl&q=low&chapter=2`, `NV.Level.devApi()` has `makeCar, toggleCar, nearestCar, carHurt, carExplode`; teleport next to a parked car (`L.cars`), `toggleCar()`, dispatch `keydown` for `KeyW / KeyD / Space`, set `L.drive.car.vx / vz` and `L.drive.df` instead of waiting.

## Hardcore and performance
- `NV.DIFF.hardcore` has `perma:true`, `ammo:.5` (reserve cap via `capOf`/`Arms.cap`) and `marks:false` (minimap/waypoints draw no markers). Use `NV.State.hardcore()` rather than reading `profile.difficulty` (old saves lack it). A failed solo operation calls `NV.State.markDead(why)` in `finish()`; `Story.runOp` then shows `UI.hardcoreOver` and `NV.State.endRun()` erases the save. The cloud copy is a tombstone (`dead` flag) in `NV.Account.upload`. Test with `#dev&allowgl&diff=hardcore&op=hack` and `NV.Level.devApi().hurtPlayer(99999)`.
- Big repeated sets use `NV.thinChunks` (per-chunk thin-instance buffers with LOD-null culling); far entities are `setEnabled(false)` in `updateEnemies` / `updateFree` / `updateTraffic`. Profile with `SceneInstrumentation` (JS is not the bottleneck; draw calls and triangles are).
- Frame loop and adaptive quality (`NV.bootEngine`, build 49). **Never change the canvas size after the scene has rendered in the same frame**: a resize clears the canvas and the browser presents that blank frame, which was the "random screen blackouts" (measured: 54 of 246 screenshots dark with the change after the render, 0 with it queued to the start of the next frame). `NV.G.queueScale(v)` and `pendTier` queue a change that the loop applies at the top of the next frame; anything that calls `engine.setHardwareScalingLevel` or `NV.Quality.apply` from the loop must go through them. Dynamic resolution moves in coarse steps (.15, .3 when far below target) with a cooldown and stops sharpening for the level once a sharpening step lowered the frame rate; nothing is measured in the first 8 s of a level or around a frame longer than .35 s. When the resolution is already at its coarsest the automatic preset steps down one tier (at most two below the detected one), **in place** (`NV.Quality.retune` / `NV.Level.applyQuality`: pipeline flags, glow layer, shadow map size and sun, mirror rate: nothing is rebuilt) and never climbs back up (a v-synced frame rate cannot show headroom, so the old climb-back flip-flopped); a new session starts from the detected tier again (`Quality.raw`). `NV.Quality.setup` returns `fx.glow` as a wrapper that remembers every mesh excluded from the glow (`fx.excl`; sky, gun, hands, light cones), so effects that do get rebuilt (`keep: oldFx`) keep them: the old in-level rebuild lost them and washed the picture out by about 25%. The frame runs inside try/catch (a game-logic error is counted in `NV.G.errs` and shown in the FPS overlay, which also shows the CPU time per frame and any GPU context resets) so one bad frame does not stop the picture or leave keys stuck. **People are never culled by the preset's detail factor alone**: the preset `lod` (.2 on the lowest presets, 3 on Ultra) multiplies every LOD distance, and at .2 a guard was low-poly at 3 m, lost parts at 6 m and was gone at 20 m while guards shoot from 17-36 m; `NV.Human`'s `lodM` and `lod()` (code-built rigs) now use `Math.max(.9, lod)` and `carProtos` `Math.max(.6, lod)`, so a person stays visible for at least ~50 m on any preset (test: `&q=howtf&op=arena&layout=arena_pillars`, put a guard 8 / 16 / 24 m in front and count `getLOD` returning null on the `i` rig instances). Ultra no longer uses a 4096 shadow map, the street mirror renders every other frame at 512 on the top tiers, pedestrians beyond 135 m are switched off. To measure on a machine without a GPU use the SceneInstrumentation counters, a CDP profile and screenshots; JS is a small part of the frame, draw calls and triangles are the cost.
- Renderer: **WebGL is the default** (`NV.bootEngine`: `NV.G.api` is `'WebGL'` or `'WebGPU'`, shown next to the build number in the FPS overlay). WebGPU is opt-in: `#webgpu` in the address turns it on (remembered in `localStorage.nv_gpu`, the flag is stripped from the address), `#gl` turns it off again. Reason: under WebGPU the story levels (the apartment, the city) were drawn black while the DOM HUD kept working, on the player's machine and in a headless WebGPU test browser (it also happened with Babylon 7.54 and 9.30 and in much older builds), while the same levels render correctly in WebGL (the Android WebView) and WebGPU draws the Training Zone fine, so do not make WebGPU the default again without checking the apartment, the city and a mission on it. `NV.gpuWatch` (WebGPU only) listens to the device's `uncapturederror` events (a one-off 'Destroyed texture' at a resize is ignored), shows a red GRAPHICS PROBLEM banner (build, Babylon version, message) after 3 errors in 6 s and switches back to WebGL by itself after 40.
- WebGPU pitfalls: it validates what WebGL forgives. A thin-instance buffer lives on the *geometry*, so every mesh that gets its own thin-instance buffer must have its own geometry: clones need `makeGeometryUnique()` (`NV.thinChunks` and the traffic-signal `sw` do this), otherwise WebGPU reports 'Instance range ... requires a larger buffer', drops the whole command buffer and the 3D view stays black. To test on WebGPU headlessly launch Chromium with `channel: 'chromium'` and `--enable-unsafe-webgpu --enable-features=Vulkan --use-vulkan=swiftshader --disable-vulkan-surface --use-angle=swiftshader`, open the game with `#webgpu` and count `WebGPU uncaptured error` console messages; `page.screenshot` works there only slowly (software rendering, about 1 to 20 fps) and `BABYLON.Tools.CreateScreenshotUsingRenderTargetAsync(engine, L.cam, size)` renders the scene off-screen, which was bright for the apartment while the canvas stayed black. The game loads the unpinned `cdn.babylonjs.com/babylon.js` (the newest Babylon, 9.x at the time of writing), so also test against the latest `babylonjs` npm package, not only an old local copy.
